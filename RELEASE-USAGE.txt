batch-rename 0.1.1 — Linux x86_64

Installation
Download batch-rename-linux-x86_64 and SHA256SUMS from the v0.1.1 GitHub release.
Verify the downloaded binary before installing into an explicit directory:
  sha256sum --check --ignore-missing SHA256SUMS
  install -Dm755 batch-rename-linux-x86_64 ./batch-rename-bin/batch-rename
  ./batch-rename-bin/batch-rename --version

The Linux executable requires the system libraries recorded in BUILD-INFO.txt.
Other platforms have not been verified. To build the tagged source with Rust:
  cargo build --release --locked -j1
No package-registry publication is needed.

Preview first
Use a backed-up folder that no other process is changing:
  ./batch-rename-bin/batch-rename --recursive --prefix reviewed_ /path/to/selected-folder
Without --commit (or -y), this prints the plan and changes nothing. Review every
source/destination and resolve collisions before choosing to add --commit
yourself. A new invocation replans; the preview is not a saved, locked transaction.

Disposable example
Use a new temporary directory, not a real-data folder:
  fixture=$(mktemp -d)
  printf 'generated A\n' > "$fixture/a.txt"
  printf 'generated B\n' > "$fixture/b.txt"
  ./batch-rename-bin/batch-rename --recursive --prefix reviewed_ "$fixture"
The fixture is retained for inspection. This example is a dry run.

Limits
Rules must produce a basename in the source directory; separators, dot/dot-dot,
NUL and colon are refused. Commit requires regular files and a filesystem that
supports hardlinks; source-file symlinks are refused. Ordinary I/O failures
trigger rollback, but restoration can also fail. In that case inspect the
retained staging directories listed in the error before retrying or moving data.
A process crash or power loss is not automatically recoverable: files may remain
in staging or final paths. Backups and manual recovery may be necessary.
Concurrent file/directory modification is unsupported. Identity checks reduce
races but do not lock the filesystem. Non-Unix identity checks are weaker.
